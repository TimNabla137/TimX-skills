# 时间与任务管理

先读当前项目 AGENTS.md，遵循其作用域、用户偏好与授权规则。语言、时区、工作时间及可用日历以当前用户和项目配置为准；不得从本 Skill 推断个人配置或既有授权。目标是推动重要工作取得可验证进展，并保护休息与生活。

## 读取当前状态

规划前，通过 lark-cli 的用户身份（`--as user`）读取当前个人 OKR、未完成待办及目标日期日历。按资源使用现有 lark-task、lark-base 或 lark-doc Skill；认证和权限问题使用 lark-shared。先查看对应 CLI 帮助和已配置资源，不能猜测命令、OKR 位置或资源 ID。无法定位时，只询问缺少的入口。

记录来源和读取时间，区分飞书确认、用户报告、推断与 UNKNOWN。读取失败时明确缺口，可以提供标明假设的候选计划，但不能把未知日历当作空闲或旧快照当作当前状态。OKR 正文日期和系统截止字段冲突时，请用户确认后再依据该日期排程。

只询问当前消息及可读资料无法确定、且会改变安排的信息，例如精力、临时硬截止或冲突的优先级；不要重复询问已知信息。

## Eisenhower Matrix：确定优先级

分别评估重要性与紧急性，标明理由。重要性依据目标贡献、交付价值和不做的后果；紧急性依据硬截止、剩余可用时间和依赖时效，不把消息频繁或任务耗时长当作紧急或重要的证据。

| 象限 | 处理方式 |
| --- | --- |
| 重要且紧急 | 优先安排能在截止前完成的工作块；发生容量冲突时说明取舍 |
| 重要但不紧急 | 主动预留连续工作块，防止长期目标被琐事挤占 |
| 紧急但不重要 | 评估简化、集中处理或委派的可能；委派仅为建议，未经授权不联系他人 |
| 不重要且不紧急 | 建议暂缓或取消，未经明确要求不删除待办 |

信息不足时将象限标为暂定并说明未知因素。用户明确指定的重点优先；象限不能替代依赖分析和容量检查。

## 核心：评估、估时、组合、排程

对纳入规划范围的每个未完成待办，明确下一步、预期产出、截止、依赖、专注要求和剩余工作量。依据任务规模、类似工作实际耗时和不确定因素给出分钟区间与预计番茄数；缺少依据时标为初估。必要时先安排一个探索番茄，再重新估计，不对模糊任务给出虚假的精确值。

默认一个番茄为 25 分钟工作、5 分钟短休；每连续四个番茄后用 15–30 分钟长休替代短休。按用户习惯与任务节奏调整。区分净工作时间和包含休息的日历占用时间，避免低估一天的负荷。

- 琐事：把性质、工具或场景相近的小任务集中进一个或几个番茄；块内列明各任务及预计耗时，保留逐项关联。
- 深度工作：按阶段产出安排连续大块时间，块内用番茄节奏休息，不穿插无关杂事；跨天任务拆成可验收的阶段。
- 周期性工作：依据已确认的频率、截止和耗时安排重复工作块。频率未知时询问，不自行假定；注明每次完成标准，明确重复范围。
- 容量不足或受依赖阻塞：明确列出暂未排入的任务及原因，不能为追求每条都有时段而制造冲突或过载。

复盘时对照预估与用户报告或可验证的实际耗时，更新剩余估计与下一次同类任务估时。没有实际耗时证据时保持未知。

## 根据请求工作

### Time Blocking：每日安排与临时重排

把任务从待办列表落实为具有开始、结束时间的日历工作块。先扣除固定日程、休息和缓冲，根据 Eisenhower Matrix、估时与精力时段安排剩余容量。Time Blocking 决定何时围绕哪个任务工作；番茄工作法决定块内工作与休息的节奏。

为每个块指定任务或阶段、产出和含休息的占用时间；深度工作块尽量连续，琐事按场景批量集中，周期工作按确认频率重复。未完成时重新估算并检查未来空闲，不无限延长当前块或自动挤占下一项日程。

- 结合当前 KR、客户承诺、硬截止、依赖和交付价值排序，落实用户明确指定的重点。尽量选出一项今日最重要的可验证进展，并说明选择依据。
- 把选中的任务写成“下一步动作 → 可审阅产物或完成证据”，标明必要依赖。估时使用合理区间并标为估计，不伪装成已测量事实。
- 先保留既有日程、午休、休息和缓冲，再放入连续工作块；杂事集中处理，番茄钟按精力选用。工作时段、午休长度和周末负荷采用用户或项目设定；缺少影响排程的设置时询问。当天已过去的时段不能继续分配。
- 超出容量时，指出冲突及推荐延期项，让用户决定真正影响承诺的取舍，不自动用晚上补齐，也不把全部空闲填满。
- 用户更新状态后，仅重排受影响的时段和任务。给出新的最重要下一步，避免重复整份计划。

### 任务整理与进度跟踪

任务不清楚时，先明确预期结果，再拆成足够启动的少量动作；不把全部待办展开成大型项目计划。需要时列出任务、下一步、完成证据、截止或依赖及信息来源。

跟进时核对已有产物、实际完成和卡点，不以“正在做”代替完成证据。对阻塞给出解除依赖的最小动作；对适合 agent 的工作，提出明确产出和用户审阅点，但建议委派不等于已经执行。

用户说“只盯进度”时，只询问进度、核对可读产物并调整计划，不制作或修改交付物。用户口头报告完成可用于重排，标为用户报告，不能声称飞书已更新。

### 晨间与晚间

晨间确认尚未明确的精力、临时事项及今日重点，然后给出可执行安排。晚间核对实际完成、未完成原因、KR 进展和明日最重要的一步；不自动把晚上安排为补工。

晨间与晚间讨论时间采用当前项目或用户设定；实际是否存在、是否启用及运行时间以自动化工具读取结果为准。此 Skill 的创建或调用不会自动创建提醒；只有用户要求时才通过自动化工具管理调度。

## 将待办落实到日历

先核对当前会话或项目明确提供的日历写入授权，在已授权的日期、规划周期和日历范围内创建或调整对应工作日程，无需对同一授权重复确认。没有写入授权时先形成可审阅的安排，再请求授权；安装或调用本 Skill 本身不构成写入授权。“只给建议”“先别写入”等后续限定优先。日期范围或目标日历无法确定时先询问。编辑 Skill 不构成执行待办排程的请求。

使用 lark-cli 用户身份，先查看 calendar 对应命令帮助，确认目标个人日历及权限。写入前读取目标范围现有日程和任务最新状态，形成具体任务—时段映射并检查冲突；保留会议、用餐、休息和缓冲。无法读取日历时暂停依赖其空闲信息的写入。

每个工作日程应包含：可辨识的任务或阶段标题、开始和结束时间、任务链接或稳定 ID、块内动作与完成标准、预计净工作时间及番茄和休息节奏。琐事块可以关联多个待办；长任务可以对应多个阶段日程。一个工作块通常建为一个事件，避免为每个短休创建零碎事件；重复规则仅用于已确认的周期性工作。

写入前检查同一任务和阶段是否已有安排，优先复用或更新本助理建立且仍在授权范围内的工作块，避免重复创建。不得挪动或覆盖无关日程、添加他人为参与者或扩大为对外邀请。任务状态不因排入日历而自动变成完成。

写入后读回核对事件 ID、任务关联、时区、时间和重复规则；汇报已排入、暂未排入及写入失败的事项。请求结果未知时先查是否已创建再重试。部分成功时保留真实结果，不声称全部已排好。临时重排只调整范围内受影响的未来工作块，保留已过去的记录；涉及取消或删除时核对具体范围与已有授权。

每次新增、改期或取消待办工作块，以及修改待办的计划日或完成状态后，按关联任务 GUID 对账日历和飞书待办：核对任务仍存在、完成状态、开始日、截止日及日程中的任务链接。已授权的对应待办计划开始日和排程说明随工作块同步，并分别读回；开始日可早于首个工作块，不必等于每个分段日期。截止日表示交付承诺，不因工作块移动而自动改写；排入日历也不表示任务完成。若已完成待办仍有未来执行块，或用户报告与飞书状态相矛盾，先核实真实状态，再决定取消工作块或修正待办。无法消除的差异要逐项报告，不能声称两边已同步。

## 飞书待办与 OKR 写入

日历按上述授权执行；任务拆分默认是建议，不自动新增待办。用户明确要求新增、修改或完成飞书待办时，读取并核对目标，仅执行已授权的条目和字段，再读回确认。目标有歧义时暂停该写入并询问；不阻塞无关的只读工作。

未经明确要求，不批量更新 OKR 或待办，也不修改授权排程范围外的日历；不因用户报告完成就自动勾选任务。不把读取权限视为写入授权，不在失败后反复重试可能重复创建的操作，先核对是否已成功。

## 输出

结论先行，按请求给出必要内容：今日重点、Eisenhower 象限与依据、任务耗时与番茄估计、日历工作块、下一步及完成证据、需要用户决定的冲突。只有有助比较时使用表格，不强制每次输出完整模板。

明确区分建议安排与已写入结果；外部写入报告目标、改动及读回结果。若无法验证，说明 UNKNOWN 或 NOT_RUN，不声称任务已完成或定时提醒已生效。
